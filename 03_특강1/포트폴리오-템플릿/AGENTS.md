# 이 폴더에서 Codex가 할 일

이 폴더는 대학생이 취업 준비를 위해 '퍼스널 브랜딩 페이지'를 만드는 템플릿이다. 채용 담당자가 이 학생의 이름을 검색하거나 AI에게 물었을 때 도착할 페이지다. 페이지는 세 부분이다: 프로필, 작업물 목록, 대표 프로젝트 케이스 스터디. 카드뉴스를 만들면 네 번째로 카드뉴스 섹션을 붙인다. 원하면 같은 내용으로 SNS용 카드뉴스도 만든다. Codex는 내용을 함께 채우고, 학생이 원하면 디자인도 자유롭게 바꾼다. 한국어로 대화한다.

## 규칙

1. 페이지의 세 부분(프로필, 작업물, 대표 프로젝트)과 `application/ld+json` 정보는 빼지 않는다. 그 밖의 레이아웃, 색, 글꼴, CSS는 학생이 원하는 대로 바꿔도 된다. 학생이 디자인을 요청하기 전에는 `{{...}}` 자리표시만 채운다.
2. 학생이 말하지 않은 사실을 지어내지 않는다. 수치, 날짜, 도구 이름, 결과, 수상, 소속은 학생이 준 것만 쓴다. 모르면 묻는다.
3. 한 번에 다 묻지 않는다. 항목 하나씩 묻고, 답을 받으면 바로 채운 뒤 다음으로 간다.
4. 학생의 말을 다듬되 뜻을 바꾸지 않는다. 과장하는 형용사(혁신적인, 열정적인, 최고의)는 넣지 않는다. 채용 담당자가 읽고 '이 사람이 무엇을 할 수 있는지' 알 수 있게 쓴다.
5. 이름 표기는 처음 받은 그대로 페이지 전체에서 똑같이 쓴다. 영문 이름도 하나로 정한다.
6. 빈 링크(LinkedIn, 데모, 코드 저장소)는 해당 줄을 삭제한다. `#`이나 빈 주소를 남기지 않는다. `<script type="application/ld+json">` 안의 빈 항목도 지운다.

## 폴더 규칙

- `my-materials/`: 학생의 과제물, 발표자료, 캡처, 프롬프트. 정보를 물어보기 전에 먼저 읽고, 거기 있는 내용은 다시 묻지 않는다. 이 폴더의 파일은 고치거나 지우지 않는다.
- `design/`: 학생이 내려받은 DESIGN.md.
- `reference/`: 카드뉴스 레퍼런스 이미지. 공개하지 않는다.
- `portfolio/`: 공개되는 페이지. 카드뉴스는 `portfolio/cardnews/`에 만든다. 여기에 넣는 파일 이름은 영문 소문자, 숫자, 하이픈으로 짓는다.
- `video/`: 쇼츠와 릴스용 영상.
- 새 파일은 이 폴더들 안에만 만든다.

## 진행 순서

학생이 "시작"이라고 하거나 AGENTS.md를 읽으라고 하면 아래 순서로 간다. 학생이 `worksheet/작업물목록.md`를 채워 두었으면 먼저 읽고, 거기 있는 내용은 다시 묻지 않는다.

### 1. 프로필 (실습 처음 5분)
- `{{NAME}}`: 이름. 영문 병기를 원하면 "홍길동 Gildong Hong"처럼 한 번에.
- `{{SCHOOL}}`: 학교, 학부(학과), 학년. 예: 「한양대학교 ERICA ○○학부 2학년」. 동명이인이 많아서 사람들은 「학교 + 학부 + 이름」으로 검색한다. 이 표기는 페이지 제목, 프로필, LinkedIn에서 똑같이 쓴다.
- `{{INTEREST_ROLE}}`: 관심 직무 하나. 예: AI 서비스 기획, LLM 애플리케이션 개발, 데이터 분석.
- `{{HEADLINE}}`: 나를 한 줄로. "무엇을 만드는 사람인지"가 보이게. 예: "LLM 에이전트로 학교 행정 문제를 푸는 서비스를 만듭니다". 학생이 어려워하면 작업물을 먼저 받고 거기서 같이 뽑는다.
- `{{ABOUT}}`: 2~3문장. 무엇에 관심이 있고, 이번 학기에 무엇을 만들었고, 어떤 일을 하고 싶은지. `{{ABOUT_SHORT}}`는 그 첫 문장.
- `{{EMAIL}}`, `{{LINKEDIN_URL}}`.

### 2. 작업물 목록 (5분)
- 이번 학기 작업물을 모두 받는다. 하나마다 이름, 기간, 맡은 역할(혼자/팀에서 무엇), 한 줄 설명, 링크.
- 그중 대표 프로젝트 하나를 고르게 한다. `{{FEATURED_*}}`에 넣는다.
- 나머지는 `WORK_CARD_START`와 `WORK_CARD_END` 사이 블록을 프로젝트 수만큼 복제해 채운다. 다 채운 뒤 두 주석 줄은 지운다. 대표 외 작업물이 없으면 블록째 지운다.

### 3. 대표 프로젝트 케이스 스터디 · 체크리스트5 (실습 다음 20분)
항목 하나씩 묻는다. 각 항목은 3~5문장.
- 문제 `{{PROBLEM}}`: 누구의 어떤 불편을 풀려고 했나? 왜 그 문제를 골랐나?
- 접근 `{{APPROACH}}`: 어떤 방식으로 풀기로 했나? 고려했다가 버린 방법이 있으면 한 문장 꼭 넣는다.
- 에이전트 설계 `{{AGENT_DESIGN}}`: 어떤 모델, 어떤 역할 분담, 어떤 도구 호출, 프롬프트는 어떻게 짰나? 실제로 쓴 프롬프트가 있으면 `{{PROMPT_SAMPLE}}`에 원문 그대로. 없으면 `<pre>` 블록 삭제.
- 결과 `{{RESULT}}`: 무엇이 됐고 무엇이 안 됐나? 안 된 것도 한 문장은 넣는다. 데모와 코드 저장소 링크(있으면).
- 배운 것 `{{LEARNED}}`: 다시 한다면 무엇을 다르게 하겠나? 2~3문장, 다음 프로젝트에 가져갈 구체적인 것.

### 4. 디자인 (원하는 만큼)
- 내용 다섯 항목(체크리스트5: 문제, 접근, 에이전트 설계, 결과, 배운 것)을 다 채웠는지 먼저 확인하고, 디자인을 바꿀지 묻는다. 학생이 처음부터 디자인을 먼저 하고 싶다고 하면 따른다. 다만 남은 시간에 내용을 못 채울 것 같으면 한 번 알려 준다.
- `design/DESIGN.md`(또는 폴더 맨 위의 `DESIGN.md`)가 있으면(학생이 getdesign.md에서 내려받아 넣은 파일) 그 파일을 읽고 색, 글꼴, 여백, 카드 모양을 페이지에 적용한다. 인터넷에서 다시 찾지 않는다. 로고나 회사 이름은 가져오지 않는다.
- `DESIGN.md`가 없는데 학생이 getdesign.md 이야기를 하면, 직접 내려받아 `design/` 폴더에 `DESIGN.md`로 넣으라고 안내한다.
- 학생이 Pinterest 이미지나 말로 분위기를 설명하면, 색과 글꼴 후보를 먼저 2~3개 보여 주고 고르게 한 뒤 적용한다.
- 바꾸기 전 상태를 `portfolio/index_이전.html`로 남겨, "되돌려줘"라고 하면 돌아갈 수 있게 한다.
- 무엇을 바탕으로 디자인했는지(예: 어떤 DESIGN.md) 페이지 맨 아래에 작게 적을지 학생에게 묻는다.
- 휴대폰 폭에서도 깨지지 않는지 확인한다.

### 5. 마무리
- `{{UPDATED}}`에 오늘 날짜(YYYY-MM-DD).
- `portfolio/index.html`에 `{{`가 하나도 남지 않았는지 확인한다. 남았으면 그 항목을 다시 묻는다.
- 브라우저로 `portfolio/index.html`을 열어보라고 안내한다.
- `checklist/내정보_일치확인.md`를 함께 보자고 안내한다.
- 제출은 배포 링크가 있으면 링크를, 없으면 `portfolio` 폴더를 `이름_퍼스널브랜딩.zip`으로 압축해 드라이브에 올리는 방법을 안내한다. 압축이나 업로드를 대신 하지 않는다.
- 배포(Vercel)는 README.md의 「공개하기」 순서를 안내만 한다. 배포를 대신 실행하지 않고, 계정 생성이나 Claim도 대신 하지 않는다.

### 6. 카드뉴스 (수업 14:30~14:50)
학생이 카드뉴스를 요청하면 퍼스널 브랜딩 페이지 내용으로 SNS에 올릴 카드를 만든다. 자세한 안내는 `guide/카드뉴스_가이드.md`.
- `portfolio/cardnews/index.html` 하나에 카드 5장을 세로로 이어 붙인다. 카드마다 다른 `<section>`으로 나누고 크기를 고정한다.
- 기본 크기는 1080×1350(세로 4:5, 인스타그램과 페이스북). 학생이 쇼츠나 릴스용을 요청하면 1080×1920(세로 9:16)으로 `portfolio/cardnews/shorts.html`을 따로 만든다. 이것은 카드 이미지이고, 쇼츠와 릴스에 게시하려면 영상으로 한 번 더 만들어야 한다고 알려 준다.
- 다섯 장의 순서는 체크리스트5를 따른다.
  1. 표지: 학교, 학부, 이름(페이지와 같은 표기)과 한 줄 소개
  2. 문제
  3. 접근과 에이전트 설계
  4. 결과(된 것과 안 된 것)
  5. 배운 것과 퍼스널 브랜딩 페이지 주소. 아직 배포 전이면 주소 대신 이름과 연락 채널(이메일이나 LinkedIn)을 넣고, 배포한 뒤 주소를 추가하라고 안내한다
- 문장은 `portfolio/index.html`에 이미 쓴 내용에서만 가져와 줄인다. 새 수치, 성과, 사람 이름을 만들지 않는다. 카드 한 장에 큰 글씨 한 문장과 작은 글씨 두세 줄을 넘기지 않는다.
- 폴더 맨 위의 `reference` 폴더에 (공개되지 않는 곳) 학생이 Pinterest에서 모은 레퍼런스 이미지가 있으면 먼저 보고, 배치와 분위기(제목 크기, 여백, 장마다 구성)를 참고한다. 레퍼런스의 사진, 로고, 문구는 가져오지 않는다. 레퍼런스가 없으면 Pinterest에서 2~3장 찾아 넣으라고 안내한다.
- 색과 글꼴은 퍼스널 브랜딩 페이지에 쓴 디자인(`DESIGN.md`가 있으면 그것)을 기본으로 하고, 레퍼런스와 어울리게 조정할지 학생에게 묻는다.
- 이미지로 저장하는 방법은 학생 환경에 맞게 안내한다. 브라우저에서 카드를 열고 화면 캡처하거나, 가능하면 카드별 PNG로 저장하는 방법을 알려 준다.
- 카드뉴스를 다 만들면 `portfolio/index.html`에 카드뉴스 섹션을 넣을지 묻는다. 넣으면 대표 프로젝트 아래에 `<section id="cardnews">`를 추가한다. 카드 PNG가 있으면 옆으로 넘겨 보는 줄로 보여 주고, 없으면 `cardnews/index.html`로 가는 링크와 카드 다섯 장의 제목을 적는다. 바꾸기 전 상태는 `portfolio/index_이전.html`로 남긴다. 휴대폰 폭에서 깨지지 않는지 확인한다.
- SNS에 올리는 일은 학생이 직접 한다. 계정에 로그인하거나 대신 게시하지 않는다.

## 하지 않는 것

- 새 프레임워크나 빌드 도구 도입 (HTML과 CSS만으로 열려야 한다)
- 학생이 주지 않은 수치, 성과, 수상, 경력 작성
- 학생 대신 SNS에 로그인하거나 게시하기
